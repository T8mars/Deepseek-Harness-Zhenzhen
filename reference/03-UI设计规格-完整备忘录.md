### 0.2 约定

- **路径约定**：DSH 源码根 = `…/scratchpad/upstream/dsh`，画布 = `…/scratchpad/upstream/canvas`；正文一律写**仓库相对路径**，如 `packages/client/ui-theme/src/styles/design-platform.css:166`。
- **证据标注**：关键事实后面带 `[路径:行]`；没有核实到的写 **“未核实”**；需要实现时再确认的写 **“待核实”**。
- **判定图例**（§1 使用）：
  - **T** = 仅改令牌即可（`03-tokens.css` 或 `overrideTokens`）；
  - **P** = 令牌 + 新增 slot 插件即可，**不改上游源码**；
  - **S** = 需要**上游源码补丁**（编号 S1–S8，§1.4）。
- **数字来源**：色值来自 `scripts/palette.py`，所有对比度由 `scripts/contrast.py` / `build_tables.py` / `canvas_map.py` 计算（WCAG 2.x 相对亮度公式，**不四舍五入过线**：4.499 判不达标）。非文本组件取 3:1（WCAG 1.4.11），普通文本 4.5:1，正文主色目标 7:1（AAA，自定目标）。
- **不含 emoji**；图标一律用 `ui-primitives` 的线性图标体系。

### 0.3 边界声明（鲸鱼娘）

1. “鲸鱼娘”是社区既有角色，**美术由用户自行提供**。本文**不绘制、不复刻、不描述**其外观，也**不给“画成什么样”的指引**；只规定“资产放哪、多大、什么格式、缺失时怎么办”。

## 1. UI 地图

### 1.1 总览

DSH 前端是“一个 `ui-theme` 管全部令牌 + 一组 `ui-*` 包通过 slot 拼装”的结构 [`docs/subsystems/slots.md`、`docs/subsystems/client-modules.md`]。因此：

- **颜色 / 字体 / 阴影**集中在 `packages/client/ui-theme/src/styles/`（`design-platform.css` 408 行：静态色阶 L4 / L85，语义 alias L166 / L284）；
- **品牌、Hero、输入框、聊天、工具、审批、设置、插件**都是有 slot 的独立包，可由插件注入；
- 没有头像、没有技能库、没有知识库、没有画布面板、没有余额显示——这些是**新增**的。

### 1.3 接入方式与级联注意

**两种接入方式**

| | A. 覆盖层（推荐） | B. 直接 fork `ui-theme` |
|---|---|---|
| 做法 | 新建 `ui-theme-zhen` 客户端插件：`ctx.theme.register({id:'zhen-tide',colorScheme,tokens})` 注册主题，`ctx.theme.overrideTokens('dsh-zhen',{name:{light,dark}})` 注入成对令牌，并用 `ctx.effect` 注入一张 `<style>`（与 `ui-theme` 自己注入样式表的方式相同） | 直接改 `design-platform.css` / `gradient-shadow-text.css` |
| 同步上游 | 冲突面小，只依赖**变量名稳定** | 408 行令牌表每次同步都冲突 |
| 首帧 | 插件加载前先显示上游蓝白，**需 S1** 压住底色 | 零闪烁 |
| 证据 | `packages/client/ui-theme/src/client/index.ts`；`packages/client/ui-layout/src/client/theme-presenter.ts:85-89`（覆盖层以行内 CSS 变量写到 `body`；令牌名不受限，裸字符串会抛错） | `packages/client/ui-theme/src/styles/*.css` |

> 与“架构与上游同步方案”备忘录对齐时，以其结论为准；本文给出的是设计视角的默认建议：**A + S1**。

**级联与特异性（实现时必须遵守）**

1. 上游把变量声明在 `body` 与 `body[data-ds-dark-theme]`（不是 `:root`）[`design-platform.css:4,85,166,284`]。覆盖必须**同时给出这两个选择器**，且样式表要在上游样式表**之后**加载。
2. macOS 桌面端的菜单填充写在 `html[data-platform='darwin'] body`，特异性更高，需要同级覆盖（`03-tokens.css` §C 已处理）。
3. `--dsw-elevation-stroke / -panel / -prominent / -soft` 在 `body, body *` 上**逐元素重声明** [`gradient-shadow-text.css:31-39`]：`overrideTokens` 的行内 `body` 覆盖**无效**，必须走样式表且使用相同选择器（`03-tokens.css` §E 已处理）。`--dsw-shadow-lv1..3` 在 `body` 上，可行内覆盖。
4. 已注册的主题**不会**写入“外观”设置行（该行只有 浅 / 深 / 跟随系统），因此用 `overrideTokens` 做默认皮肤，而不是新增一个需要用户手选的主题 [`packages/client/ui-theme/src/theme-settings.ts`]。
5. **不要**全局设置 `--dsw-focus-ring-color`：指针模态会把它置为透明，焦点环颜色应回落到 `state-business-primary` [`packages/client/ui-theme/src/styles/focus.css`]。
6. 圆角阶梯 `--dsw-radius-xs…panel = 4/8/12/16/20/28`、`corner-shape: superellipse(1.5)` 及“全圆角配 `corner-shape: round`”的约定**保持不变**（`docs/ui-radius.md`）。

## 2. 设计令牌

### 2.1 设计语言：「潮汐 Tide」

**原则**

1. 内容优先：聊天、代码、画布产物是主角；装饰只出现在 **Hero、空态、加载、角色状态环** 四处。
2. **一个强调色 + 一个副色**：海青为唯一强调；海葵紫仅用于“创作 / 画布 / 技能”，不与状态色冲突。
3. **暖色保留给状态**（成功绿、警告琥珀、错误红），不做装饰。
4. 阴影带轻微青色（`rgba(8,70,88,…)`）而非纯黑，暗色加一圈极淡的海青辉光仅用于 Composer。
5. 装饰动效最多三种（水纹、气泡、潮汐漂移），全部有 `prefers-reduced-motion` 归零。

**原创抽象母题（只允许这五种）**

| 母题 | 几何 | 出现位置 | 动效（提案值，原型阶段可调） |
|---|---|---|---|
| 水纹 ripple | 同心圆 3 环，半径 24 / 48 / 72px，描边 `border-l2`（0.5px） | 角色状态环、Hero 背景 | 缩放 0.8→1.6、透明 0.5→0，2400ms，错峰 400ms；`--dsw-zhen-duration-ripple` |
| 气泡 bubble | 圆 + 高光弧，直径 4–14px，6–10 个 | Hero、空态 | 上升 120px，5200ms；`--dsw-zhen-duration-bubble` |
| 潮汐带 tide band | 两层缓动正弦渐变带（`zhen-tide-from → zhen-tide-to`），底部 160px | Hero 底部、引导页 | 水平漂移 48s 线性循环；`--dsw-zhen-duration-drift` |
| 等深线 contour | 0.5px 不规则闭合线族 | 空态插画底纹、关于页 | 静态 |
| 焦散光 caustic | 径向渐变光斑（`zhen-glow`） | Composer 暗色辉光、卡片悬停 | 静态或 0.3s 淡入 |

**禁止**：鲸 / 鱼 / 尾 / 喷水柱的轮廓；任何近似 DeepSeek 官方鲸鱼标志的单曲线；任何对“鲸鱼娘”外形的抽象化、剪影化。

### 2.8 与画布主题模板 JSON 的映射

画布主题模板 schema：`{schema:'t8-theme-template', version:2, id, name, description, author, legacyStyle:'tech'|'pixel', visuals:{style,intensity,iconPack,canvasPattern,nodeFrame,headerMark}, music?, modes:{light:{tokens},dark:{tokens}}}`，共 **36 个 tokens**（按 `ThemeTokens` 接口逐项计数），由 `applyTheme.ts` 映射为 `document.documentElement` 上的 `--t8-*` 变量 [`canvas: docs/theme-design-guide.md`、`src/theme/types.ts`、`src/theme/applyTheme.ts`]。

要点：

- 画布内置 `tech` 模板：亮 accent `#0284c7`，暗 accent `#38bdf8`，secondary 紫 `#7c3aed / #a78bfa`；暗色端口色 `#7dd3fc / #fcd34d / #fda4af / #c4b5fd` [`canvas: src/theme/defaultTemplates.ts` techDark / techLight]。DSH-zhen 的“海青 + 紫副色 + 同一组端口色”与 `tech` 同族，所以画布与 DSH 并排使用不会违和；暗色端口色被**原样沿用**以保持跨产品一致。
- 画布校验只对 **hex** 色计算 5 组对比度（appBg/textMain、panelBg/textMain、nodeBg/textMain、panelBg/textMuted、accent/accentText，阈值 4.5）；`rgba(...)` 不会被检查 [`canvas: src/theme/validateTheme.ts`]。因此映射里与这 5 组相关的色值一律用**不透明 hex**（画布内置模板的 `nodeBg` 是 rgba，我们改成 hex）。
- `visuals.style` 是固定枚举（含 `plain`、`tech`、`pixel` 等），后端 `routes/themes.js` 白名单，未知值回退；**新增视觉风格需要改画布代码（本轮不改）**。建议用 `style:'tech'` + `canvasPattern:'dots'` + `nodeFrame:'glass'` + `intensity:'subtle'`。
- 自定义主题目录：`~/zhenzhen/theme-templates`（Windows `D:\zhenzhen\theme-templates`）。
- 画布 token **没有** corner-shape 概念，圆角数值相同但角形不同（未核实 `applyTheme.ts` 是否注入 `corner-shape`），差异可接受。

## 3. 角色美术资产槽位规范（核心）

> **本节规定“容器”，不规定“内容”。** 角色形象由用户提供；本节不描述、不暗示其外观。凡涉及“视觉重心”“裁切”，一律由用户在 `manifest.json` 中以坐标声明，UI 只负责遮罩与缩放。

### 3.1 总则

1. **一份母版 + 焦点裁切**：用户提供 1 份高分辨率透明母版（建议长边 ≥2304px；PNG / PSD / SVG 均可，**不随包发布**，放 `art-src/`）。其余槽位优先使用用户提供的专用裁切稿；缺省时 UI 按 manifest 的 `focus {x,y,scale}`（0–1 归一化坐标）做**纯 CSS 裁切**（`object-position` + 圆形 / 超椭圆遮罩），因此用户不必一次交付所有尺寸。
2. **不烘焙**：不得在图里烘焙背景、投影、光晕、描边光、文字、水印。光晕与分离感由 CSS 使用 `--dsw-alias-zhen-glow` / `--dsw-alias-zhen-foam` 提供。
3. **目录与命名**（建议；资产随包方式与 `ui-theme` 的 Montserrat 同法——放进包内并由 `tsdown` 复制，CSS `url()` 相对引用 [`packages/client/ui-theme/tsdown.config.ts:9`、`brand-font.css`]；DSH-zhen 中具体用 `?url` 导入还是复制，**待核实**）：

```
packages/client/ui-zhen-art/            # 包名仅为示例；建议与代码包分仓、可选安装
  assets/character/<set-id>/            # set-id: 小写 ASCII + 连字符，如 default、spring-2027
    manifest.json                       # 见 §3.6
    LICENSE.txt   CREDITS.md            # 见 §3.8
    hero/    portrait@2x.webp  portrait@3x.webp  [portrait-dark@2x.webp]
    marks/   sidebar-96.svg|webp   hero-136.svg|webp   chat-112.svg|webp
    states/  idle.webp  thinking.webp  tool.webp  approval.webp  success.webp  error.webp   # 192×192
    loading/ still.webp  loop.webp
    empty/   kb.webp  skills.webp  canvas-offline.webp  no-result.webp  gateway-error.webp  no-balance.webp
    brand/   favicon.svg  favicon-dark.svg  app-1104.png  installer-brand.png ...   # §3.5
    skins/<skin-id>/...                 # 与上面同构，仅放有差异的槽位
```
   命名规则：全小写 ASCII、连字符、`@2x/@3x` 后缀；**文件名不含中文、不含版本号**（版本写在 manifest）；状态文件名固定为 6 个 key（`idle thinking tool approval success error`）。
4. **格式取舍**

| 格式 | 优点 | 缺点 | 用在哪 |
|---|---|---|---|
| SVG | 无损缩放、体积小、可随主题改色 | 只适合矢量稿；复杂渐变 / 笔触体积会暴涨 | 三种 mark、favicon、降级图形 |
| WebP（带 alpha） | 体积小、支持透明与动画、Chromium / Electron 原生 | 极少数老环境不支持（可用 PNG 兜底） | 立绘、状态图、空态、loading 单帧 |
| APNG | 兼容性好、透明动画 | 体积大、无法控制播放 | 仅在 WebP 动画不可用时兜底 |
| Lottie | 矢量动画、可编程 | 需引入运行时；体积与性能**未核实** | **不推荐**；用“静态图 + CSS 微动效”代替 |
| PNG | 万能 | 体积大 | 桌面 / PWA 图标、安装器横幅（BMP 前置） |

   AVIF 未纳入（编码工具链与旧版 Safari 兼容性**未核实**）。动效优先 **静态 WebP / SVG + CSS**（呼吸、水纹、淡入），不用长帧序列。
5. **暗色背景处理**：
   - 默认**同一份透明资产**用于亮 / 暗两套主题；暗色分离感由 CSS `filter: drop-shadow(0 0 12px var(--dsw-alias-zhen-glow))` 提供。
   - 导出时使用**去底色（un-matte）**的透明边缘，避免白边 / 黑边；半透明抗锯齿像素须按**预乘 alpha 无关**的方式导出。
   - 仅当美术在暗底上确实不可用时，才提供 `*-dark` 变体，并在 manifest 的 `variants.dark` 声明；UI 优先取变体，缺省回退同一资产。
   - 验收时必须在 4 种底色上预览：`#F4F9FA`、`#FFFFFF`（亮）、`#0A1418`、`#14242A`（暗）。
6. **体积预算**（baseline，均为提案，原型阶段可调）：首屏必需资产（`sidebar-mark` + `hero-mark` + `hero-portrait@2x`）合计 **≤150KB**；全部随包资产（不含桌面安装资源）**≤1MB**；单个季节皮肤 **≤600KB**；超预算 CI 报错。
7. **加载策略**：`sidebar-mark` / `hero-mark` 同步加载（可内联为 data URI，≤8KB / ≤12KB）；`hero-portrait` 懒加载，到位后淡入 200ms（`prefers-reduced-motion` 时无动画）；状态图 / 空态图按需加载并缓存；加载前**预留盒子尺寸**，避免布局抖动。
8. **色彩与无障碍**：sRGB；装饰图 `alt=""` + `aria-hidden="true"`；承载状态语义的图由文字标签（`aria-live="polite"`）负责朗读，图本身不是唯一信息源。

### 3.3 六个 Agent 状态

**状态机**

```
idle ──发送──> thinking ──调用工具──> tool-running ──需要确认──> awaiting-approval
  ▲               │  ▲                    │  ▲                         │
  │               │  └────── 工具返回 ─────┘  └──── 允许一次 ─────────────┘
  │               └──完成──> success ──3s──> idle        拒绝 ──> thinking / idle
  └──用户处理 / 下次发送── error <── 任一状态失败
```

| 状态 | 触发（DSH 数据源，实现时以源码为准——钩子名**待核实**） | UI 编码（令牌 / 形状 / 动效） | 文案 key（i18n）与朗读 | 美术需求 | 降级 |
|---|---|---|---|---|---|
| **idle** 空闲 | 无运行中的 turn | 环色 `state-idle-primary`，静态；无动效 | `zhen.state.idle` “待命”（不朗读） | 一张“默认姿态 / 表情”变体 | Tide Orb 静态 |
| **thinking** 思考 | turn 运行中，尚无进行中的工具调用，推理流在输出 | 环色 `label-deep-diving`；标签用 `TextShimmer` 扫光；单环水纹 2400ms；超过 30s 追加已用时间 | `zhen.state.thinking` “思考中”，`aria-live=polite` | 一张“思考”变体 | Orb + 水纹 |
| **tool-running** 工具执行 | 存在进行中的 `tool.call.*`（含 `mcp__*` 画布调用） | 环色 `state-business-primary`，旋转弧（同 `StateDot` 的 ongoing） | `zhen.state.tool` “正在调用 {tool}” | 一张“执行”变体 | Orb + 旋转弧 |
| **awaiting-approval** 等待确认 | 存在待决审批交互（决策仅“允许一次 / 拒绝”） | 环色 `state-warn-primary`，缓慢脉冲 1.6s（可关闭）；chip 展开显示按钮提示 | `zhen.state.approval` “等待你确认”，**必须朗读** | 一张“询问”变体 | Orb + 脉冲环 |
| **success** 完成 | turn 正常结束 | 环色 `state-success-primary`，一次性“落定”600ms，保持 3s 后回 idle（淡出 200ms） | `zhen.state.success` “已完成” | 一张“完成”变体 | Orb + 勾 |
| **error** 出错 | turn 失败、工具失败、网关错误（401 / 429 / 503 `model_not_found`） | 环色 `state-error-primary`，静态（**不抖动**）；保留到下次发送或手动关闭；旁带“重试”按钮 | `zhen.state.error` “出错了”+ 人话原因 | 一张“出错”变体 | Orb + 感叹 |

规则：

- “美术需求”列只声明**每个状态需要一张语义可区分的变体**，具体画法完全由美术提供方决定，本文不作规定。
- 与 `StateDot` 的五态对应：`idle→idle`，`thinking/tool→ongoing`，`approval→warning`，`success→done`，`error→error` [`packages/client/ui-primitives/src/StateDot.module.css`]。侧栏会话行继续用 `StateDot`，**角色 chip 只反映当前会话**。
- 每个状态最短显示 300ms，避免闪烁；多个状态同时成立时优先级 `error > awaiting-approval > tool-running > thinking > success > idle`。
- 6 张状态图**同画布、同锚点、同包围盒**，差异须在 28px 下无需靠颜色即可分辨（形状 / 姿态差异由美术自定）；颜色、环、徽标全部由 UI 令牌提供，所以美术**无需做颜色变体**。
- 位置：Composer 上方 `conversation.composer.dock`（28px chip + 12/18 标签）；审批卡 96px；画布联动面板 40px；turn 结尾用 `conversation.chat.turnTail` 放完成 / 出错小标记。

### 3.7 降级策略

## 7. Seedance 网关对 UI 的影响

> 来源：`https://api.seedance.nz/docs/llms.txt`（本轮通过 WebFetch 读取）。

### 7.1 接口事实

| 项 | 事实 | UI 含义 |
|---|---|---|
| 基础 | Base URL `https://api.seedance.nz`；所有请求 `Authorization: Bearer sk-…`；密钥在 `/keys` 创建 | 引导页指向 `api.seedance.nz/keys` |
| 对话 | `POST /v1/chat/completions`，OpenAI Chat Completions 风格，同步，可流式；**未提及 Anthropic 兼容端点** | DSH 里只能选 `openai-completions` 协议 |
| 模型清单 | **没有** `GET /v1/models` | “获取可用模型”必失败 → 手写清单 + 提示 |
| 默认模型 | `deepseek/deepseek-v4.1-flash`：上下文 262,144；图像输入、工具、推理、流式、缓存、结构化输出；`max_tokens` **包含推理 token** | 能力徽标；`max_tokens` 帮助文案 |
| 其他对话模型 | `deepseek/deepseek-v4-flash-vision-exp`、`glm/glm-5.3(-flash)`、`qwen/qwen3.8-*`、`zhenzhen/*`、`kimi-k3` 等 | 模型选择器按厂商分组 |
| 余额 | `GET /api/usage/wallet/` → `data.{object:'wallet_balance', quota, used_quota, total_available, amount (人民币展示余额), used_amount, display_type, username, group}`；与 `GET /api/usage/token/` 不是一个东西 | 胶囊显示 `amount`；别混用两个接口 |
| 单任务计费 | `usage.amount`（人民币；失败 / 退款为 0），位置因端点而异：`data.usage`、`usage` 或 `task.usage` | 费用展示需适配三处位置 |
| 媒体生成 | 全部为**异步提交 + 轮询**（建议间隔 3–5s）：`/v1/videos`、`/v2/video_generation`、`/v1/image/generations`、`/v1/audio/generations`、`/v1/3d/generations`、`/v1/music/generations`、`/v1/midjourney/generations`；上传 `/v1/files/upload`（30 次 / 分钟） | 任务看板、轮询节流 |
| 结果 | 结果 URL 约 24 小时过期；失败任务退款 | 倒计时、完成即保存、失败显示“已退款” |
| 错误 | 400、401、429、503 `model_not_found` | §7.4 文案表 |
| 安全 | 文档提示密钥应放服务端；**没有 CORS 说明** | 余额 / 计费调用走 Host，不要在浏览器直连 |

### 7.2 对架构的约束

- DSH 的密钥是**只写**的，页面只拿脱敏描述，明文存 `$DSH_HOME/.credentials.yaml` [`docs/user/guide/providers.zh.md`]。因此**余额、计费、轮询**不能写成纯前端 UI，必须有一个 **Host 侧插件**（Remote method）读取凭据后去调 Seedance，前端只订阅结果。
- 画布 MCP 若要提交媒体任务，也应经同一 Host 通道记录费用，否则任务看板拿不到数据（契约以 MCP 方案为准）。

### 7.3 配置草案（待实测）

```yaml
# $DSH_HOME/profiles/<profile>/cordis.patch.yml  —— 来自 providers.zh.md 的示例结构
- id: llm-pi-ai
  config:
    providers:
      seedance:
        api: openai-completions
        baseURL: https://api.seedance.nz/v1     # 是否需要 /v1：待核实
        apiKeyEnv: SEEDANCE_API_KEY
        models:
          - id: deepseek/deepseek-v4.1-flash
            input: [text, image]
```

> 上下文窗口、最大输出等字段按 `providers.zh.md` 的模型选项手填；`id` 含斜杠，需确认 DSH 的模型选择器与路由对斜杠 id 无特殊处理（**未核实**）。

### 7.4 错误文案表（提案）

| 触发 | 人话文案（zh） | 动作 | 角色状态 |
|---|---|---|---|
| 401 | “密钥无效或已停用。请检查是否复制完整。” | [检查密钥] | error |
| 429 | “请求太频繁，{n} 秒后自动重试。” | 倒计时 + [立即重试] | error（轻） |
