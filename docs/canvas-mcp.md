# T8 画布连接与创作规划

在“连接”页点击“检测本机画布”，选择找到的 Agent 工具安装，再信任连接。

画布更新后若提示`CLI_CHANGED`，先重新预览当前工具目录、核对摘要和版本，
再在连接页重新信任；不要手改pin或复制文件覆盖安装目录。3.3.7源码后端的
两个状态接口及HTTP兼容字段已通过只读复核；DSH兼容报告同时支持原生平铺
状态与旧嵌套报告。接口响应不表示已配对，后续权限仍在画布窗口确认。
当前复核与交接见[3.3.7说明](handoffs/canvas-agent-v3.3.7-review.md)。
也可手动选择已有 `zcanvas-cli` 目录。DSH-zhen 复用
该 CLI 的实例发现、完整版本/摘要握手和 secureStore，不读取明文设置。
连接页可显式发起配对；首次配对及所需范围由画布窗口批准。多个实例时填入
目标实例 ID，重开连接页会保留这个选择。

检测只读取画布安装器的默认目录、显式安装目录及两处受管理技能标记；
不会扫描磁盘、导入 CLI 代码、读取配对凭据或连接应用。选择检测结果后，
连接会核对那次检测的完整目录摘要；期间发生变化会拒绝，不覆盖原连接。
目录、工具版本和摘要可展开查看。检测到安装不等于已兼容或已配对。

开发源码 CLI 和安装版 CLI 可能不同；不要因工具版本名称相同就替换。
以实际画布返回的完整兼容报告为准，不复制工具覆盖安装目录、不跳过握手。

## 在连接页完成配对

1. 启动画布，信任工具目录并检查连接。
2. 点击“在画布发起配对”，核对本页与画布窗口中的验证码；在画布窗口选择权限并批准。
3. 返回点击“完成配对”。尚未批准会继续等待；拒绝、过期或一次性凭据已失效会显示实际状态，不自动重新请求。

默认申请读取画布、任务和素材。需要素材交接或浏览器移交时，发起前勾选
额外权限；应用工作流时可单独勾选 canvas:write，执行生成时可独立勾选 run:execute。默认均不申请。已存在的 CLI 配对
可能拥有更多权限，界面显示的是画布实际授予的范围。重新配对会更新该实例
共享的 CLI 登录，其他使用同一工具的会话也会使用新配对。

## 从连接页预览并应用工作流

点击“读取可用画布”，选择目标，输入创作目标并预览。支持图片、图片编辑、视频、视频编辑、音频/
音乐、剧本和Story，默认一个经济档候选。可展开“选择画布模型”，按模型或
平台名称读取目标画布的公开目录；只有原生核验可执行的模型可以明确选取，
凭据和线路仍在画布配置。留空由画布推荐，明确选择后不会自动换用其他模型。
媒体方案也可指定文本/参考理解模型；参考兼容由原生决策核验。
展开“参考素材”读取目标项目素材库，可查询、分页、明确加入或替换当前版本，
并用上移/下移安排顺序。图片编辑与视频编辑必须选参考；同一ID不重复加入，
当前最多16项。原生内容变更时重新选择并预览，已有选择不会自动换版本。
目录只返回元数据；“大小未提供”不表示空文件。普通视频的参考请使用视频编辑入口。
送审及应用前会重读内容身份，原生事务内完整复核仍待[画布交接](handoffs/canvas-agent-reference-assets.md)。

在“候选与输出设置”选择策略、图片/视频1–8候选、画面比例及视频/Story时长。
最终规格由原生模型决策校验；界面中的计划模型和参数来自实际返回的方案，
不一致时不进入审批。音频、剧本与Story的界面先保持单候选。核对方案后勾选
确认，再送到画布窗口。画布窗口批准后，返回点击“检查窗口审批并应用”。
未批准时只等待；拒绝时不写入。应用只创建或调整工作流，不运行生成。

模型状态仅代表本次读取；预览时会再次核验，同一模型仍需后续运行报价和
窗口审批。失效选择会保留名称并提示重新读取。更多范围与隔离验证见
[0049](decisions/0049-native-model-workflows.md)，原生协议缺口见
[画布Agent交接](handoffs/canvas-agent-api-coverage.md)。

应用需要上方配对授予的修改画布权限；可以先用只读权限预览。十个 Agent
工具仍只检查与规划。聊天中最终成功的原生创作计划会列在本页供选择；选择
后核对完整目标，再送到窗口，不会重新规划。待选列表仅保留本次Host的十六项；
未选项重启后消失，已选进度仍保存。素材预览、交付与运行报价不进入创作计划列表。
断线或重启中断
会显示“结果尚未确认”，先检查原画布，不提供该项重发按钮。原生明确拒绝
失效计划时可重新预览。范围、协议与测试限制见[决策 0025](decisions/0025-native-canvas-workflow-review.md)。

聊天交接与原生工作树验证见[决策 0026](decisions/0026-native-canvas-chat-plan-handoff.md)。
开发者可在核对画布自己的工作规则和依赖后运行：

```powershell
npm run verify:canvas-native -- --canvas-root "D:\Example\T8-penguin-canvas"
```

将示例替换为可信的源码开发目录。此命令只使用新建系统临时库，验证原生业务
路由和Patch落库；窗口批准由测试IPC模拟。当前只在本机Windows验证，不等同于
安装版、真实窗口、Provider实网或付费验收。

验证码只在连接页用于人工核对；轮询密钥和访问令牌只经原生 secureStore，
不进入模型工具、Remote 结果或 DSH 的进度文件。进度文件仅保存非秘密引用，
支持 Host 重启后继续。发起/完成请求在本 Host 合并并发调用；没有自动批准、
自动轮询或付费执行。另一份 CLI 若在网络等待期间替换待配对记录，DSH 会
检测后拒绝覆盖。最新画布工作区另有未发布的原生存储协调修复，保持v1格式，
在实际提交与清理时再次核对身份；只对采用新版协调器的进程提供保护。
旧版写入器、其他文件系统和真实安装版并发仍未验收，本适配器不替代原生事务。

“读取创作能力”显示当前高层工具的名称、版本和可直接使用的操作。
当前审阅的画布快照有 39 项能力、73 个 L0 操作，涉及图像、视频、音频、
剧本、Story、编辑、比较、运行预览、素材与交付预览。这是规划范围，
不表示已完成写入、付费生成或交付。

## 会话中的入口

DSH 中工具通常带 `mcp__t8canvas__` 前缀，按会话实际列出的完整名称调用。

| 工具 | 用途 |
|---|---|
| `canvas_status` | 返回画布原始兼容报告；不因报告有响应就绕过不兼容 |
| `canvas_workspaces` | 获取配对允许的项目、画布 ID 和版本 |
| `canvas_capabilities` | 获取画布现有创作能力与就绪状态 |
| `canvas_models` | 获取模型目录；不发起生成 |
| `canvas_capability_graph` | 获取现有能力图谱 |
| `canvas_task_status` | 查询已有 run intent，不能重发任务 |
| `canvas_creator_session` | 读取已有创作会话 |
| `canvas_capability_tools` | 核对本机 CLI 与画布的版本化高层能力、操作和权限范围 |
| `canvas_inspect` | 读取/验证/模拟当前画布，搜索素材和子流程 |
| `canvas_plan` | 对精确能力版本生成方案、预览或只读核验 |

`canvas_inspect` 只转发画布现成的八个工具：`inspectCanvas`、
`inspectNodeSchema`、`inspectRun`、`searchAssets`、`searchSubflows`、
`validateCanvas`、`simulateExecutionPlan`、`estimateRun`。必须指定项目和
画布；省略请求 ID 时由适配器生成，结果会核对这些引用并保留画布报告的
revision。它不能替代后续写入时的版本检查。
模拟不会应用修改；费用未知仍显示未知。

`canvas_plan` 使用实时清单中的 `tool`、`version`、`operation`，以及
`projectId`、`canvasId` 和高层 `input`。例如以下仅演示结构，ID 必须来自
实际工作空间，版本必须来自实时清单：

```json
{
  "tool": "zcanvas_create_image",
  "version": "0.1.0-dev",
  "operation": "plan",
  "projectId": "EXAMPLE_PROJECT",
  "canvasId": "EXAMPLE_CANVAS",
  "input": { "prompt": "EXAMPLE ONLY: describe the intended image here." }
}
```

只接受该能力声明的 `plan`、`preview`、`inspect` 或 `verify` L0 操作。
请求不能带底层路由、SQL、shell、凭据、Provider 请求或任意节点写入载体。
输入有大小和深度上限。完整字段、业务校验和权限仍由画布原有控制面处理，
适配器不重新实现节点、模型或创作执行器。

规划可能更新画布的内存方案，并使旧预览失效；保留最新返回的 planId、
摘要、版本与待补充信息。规划结果不等于审批、报价保证或已受理任务。
本地素材导入/交付预览可能需要 `asset:read`、`asset:transfer` 等已有配对
范围，运行预览需要 `run:read`，浏览器交接预览需要 `browser:handoff`。
权限不足不会自动升权。浏览器交接只返回预览信息，不打开或控制浏览器。

## 更新、故障与执行边界

CLI 的完整文件及资源闭包固定为用户审阅的摘要。内容变化时旧连接拒绝
调用；重新审阅连接后，清理仅属于该 CLI 的旧 CommonJS 缓存，避免旧代码
配上新资源。业务请求继续走原 CLI 握手与 secureStore，不走环境变量令牌。

每次规划会核对本机与在线高层清单的协议、版本、摘要、能力、操作和
权限范围，再经同一原始 CLI 发出一次 L0 请求。返回值还须匹配能力版本、
项目、画布、请求 ID、摘要及零写入/零 Provider 调用声明。传输失败不
改走其他端点或自动重发；重新规划应明确取得新的方案引用。

返回内容会去除凭据字段、URL 参数与片段，避免将秘密带进模型。完整素材
URL 和浏览器交接的实际打开仍需后续专门交接路径。CLI 按当前用户权限
运行，这个连接器不是操作系统沙箱。

`apply`、`run`、审批完成、生成提交、任务重试、文件导入、交付打包暂未
通过此 MCP 开放。付费链仍需要报价/预览、DSH 审批、画布窗口权威审批、
单次提交及受理后的只查询；原画布模糊受理后POST重发已在工作源码限定修复，
尚未生产发布，不能以规划入口绕过。

连接页现在提供独立人工运行流程：读取节点 → 查看原生执行范围/服务/模型 →
核对且接受费用未知 → 画布窗口批准 → 单次提交。缺少新版runControl保证的
画布拒绝启用此流程。回执不明仅查询原operationId，404也不重新提交。
本地只保留一份当前运行引用。其他运行可从“任务中心 → 画布任务”选择画布后读取，包含此前方案已提交的
任务，最多100条；已知引用可直接查询。列表状态和产物核验分开显示，只有
完整且一致的原生证据才展示核验通过。不会保存新的付费账本。详见[0028](decisions/0028-native-canvas-task-center.md)。
原任务和创作会话MCP查询必须填写id、projectId、canvasId。详见[0027](decisions/0027-canvas-run-approval-recovery.md)。

## 已有验证

`npm run check` 包括 C10/C16 的真实 SDK、DSH MCP 客户端、ToolRuntime、
Host/Remote 编解码以及合成 CLI 传输测试。39 项能力的 73 个操作保留精确
版本和权限，拒绝漂移、过期配对、非 L0 请求与错配结果。

```powershell
node scripts/check-canvas-contract.mjs
```

该额外检查读取固定提交和摘要的公开画布策略校验器，在临时目录使用
无副作用的合成 dispatch：73 个直接操作通过，123 个非直接操作被原始
策略拒绝，随后清理。它不执行原始业务处理器、不读取数据库，不替代
已安装画布、真实创作成果、用户项目或浏览器界面验收。
