# 更新源码版 DSH-zhen

此入口更新你克隆的 DSH-zhen 源码，并在下次启动时构建和换装扩展包。
它跟进本项目的 `main`，保留已发布 DSH 依赖的精确锁定，不更新画布。
需要 Git、Node.js 22.19.0或以上及仓库访问权限；下载ZIP的目录不能直接使用。
它不是独立安装器，也不替代未来签名安装包的生产自动更新。

## 手动更新

先关闭运行 DSH 的终端服务，再双击根目录 `update-dsh-zhen.cmd`。
程序展示当前提交、候选提交和变更文件数量；输入 `UPDATE` 才更新源码，
取消则保留当前版本。完成后重新双击 `start-dsh-zhen.cmd`。
启动器会重新构建、检查类型、打包，再经官方CLI换装；依赖变化时按锁文件
无安装脚本地准备依赖。构建或准备失败时不会启动Host，请保留报错现场。

也可以先检查，再用显示的完整提交编号更新：

```powershell
node scripts/update-local.mjs --check
node scripts/update-local.mjs --apply <完整候选提交编号>
```

检查与更新之间main变化时拒绝执行，需重新检查。程序不自动暂存、合并分叉、
变基、清理目录或丢弃提交；有修改、未跟踪文件、未完成Git操作、隐藏工作树
改动的索引标记或游离检出时停止更新。请按自己的工作流先保存修改。
本地提交领先main时保留；main尚未包含你的提交时不会覆盖分支。

## 可选：下次启动自动更新

默认关闭。启用表示信任本项目 **main开发通道中的代码**；它可能尚未形成
正式发行版，也不表示GitHub Actions已通过。开启后在启动前检查并快进，
通常每天至多一次；本地改动或分叉时跳过并启动当前源码。网络或仓库访问
失败时也保留当前源码。若已尝试快进而Git报错，则停止启动，保留现场供核对。

```powershell
node scripts/update-local.mjs --automatic on
# 关闭
node scripts/update-local.mjs --automatic off
# 本次跳过源码自动检查，仍执行正常构建和配置检查
npm start -- --skip-source-update
```

成功更新后启动器使用新的Node进程，不沿用内存里的旧脚本。Ctrl+C取消检查
时不继续启动，不自动重试。进程被强制结束或磁盘故障时仍需人工核对；程序
不以自动reset或删除文件尝试恢复。此前的提交保留在Git历史，本地更新记录
保留上一提交编号，构建包按摘要留存在`.runtime/packages/`。

## 保留资料与访问边界

更新器先占用与启动器相同的本机端口和进程租约，运行中的Host或其他启动器
会阻止下载与快进。仅允许本项目的GitHub HTTPS origin，不改写远端地址。
私有仓库通过Git已有的本机身份读取；程序不提取令牌，也不把应用中保存的
GitHub或Seedance令牌交给Git。不能访问时停止并保留当前版本。

候选所有提交树都检查四个本地专用根文件、`创作资料/`及保留目录；中间提交曾出现而
最终已删除，也会拒绝。链接、子模块及超过1000个提交的历史需人工审阅。
下载使用临时引用，结束或正常取消后清理，不改写origin/main、标签或
FETCH_HEAD。快进禁用Git hooks与自动暂存，并拒绝覆盖被忽略的现存文件；
本地角色包、资料和四份研究文件不能靠忽略规则被静默覆盖。
这些行为依据[Git merge文档](https://git-scm.com/docs/git-merge)及
[Git fetch文档](https://git-scm.com/docs/git-fetch)。

更新设置仅位于`.runtime/source-update.json`；不读取凭据布局、会话、知识库
正文或画布设置。它更新当前源码检出，仍需使用本项目启动入口，不能替其他
直接调用官方CLI的进程做协调。没有发行签名、干净机器安装、真实跨版本
GitHub更新及回滚的完整验收，不能宣称生产安装更新完成。
