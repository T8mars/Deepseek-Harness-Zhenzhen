# 0116 · 恢复管理来源的逐项调用审阅

技能市场、本地导入和 GitHub 恢复来源此前全部保持只读，缺少正式调用批准入口。现在在市场与备份恢复页增加「恢复来源审阅」：按页列出当前配置中的原活动版本、位置、原启用项和停用项，用户逐项核对并确认后才允许调用，也可暂停。

三类原服务继续使用恢复时的只读模式，市场数据库不改为可写，GitHub 不重建普通启动实例。新的调用检查只选择原活动版本，原待更新版本、个人副本、保留版本及自动更新偏好保持；批准不会应用 pending、下载、运行附带程序或授予其他工具与画布权限。本地导入沿用原目录及后续修改的信任范围，界面明确说明。文件夹来源仍在原审阅卡中分别处理。管理操作的拒绝信息也明确区分调用许可和整个恢复应用的启用，不再在已允许调用后笼统声称仍未审阅。

自有 `managed-skill-consent.json` 将决定绑定到固定 home、来源文件身份与修订、配置档和确切来源/版本标识。Host 在准备与提交前后核对实际服务、当前配置和来源；运行提供者在读取前后检查决定。不同配置不能共享批准，配置被替换、来源变化、坏审阅文件或读取中撤销都会阻止旧定义。否定缓存和批准索引避免为未批准的大量条目读取正文；自有观察器及明确操作使目录失效。

批准不改原来源记录，不开启管理写入或自动更新，也不激活整个应用。再次备份仍保留原选择，新的恢复 home 不继承调用批准。每页20项，保留全部最多40032个来源的数量与分页，不借用普通市场页面的50项展示上限；后续页批准会返回同一页。
