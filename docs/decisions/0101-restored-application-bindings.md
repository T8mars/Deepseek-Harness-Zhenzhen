# 0101 · 恢复候选的应用路径配置与记录装配

原先各组件分别恢复，会话、附件和工作区库存无法被同一配置直接读回。本次在新组合候选的最终文件基线建立前，生成独立的应用配置覆盖层，将公开 SDK 提供者关联到实际恢复目录，并把已覆盖的自有记录装配到候选应用目录。已有候选和用户运行目录不改。

## 实现

- 使用固定已发布 0.2.1-rc.2 的公开配置读取、软件包解析及 patch 组合 API，只读清单和表达式数据；不调用会改写清单的配置装载函数，不加载归档模块或执行表达式。读取有文件身份、字节和总量检查，越界、链接、重复 ID 或整个 config 是表达式时给出审阅原因。
- 按模块身份匹配提供者，支持改过的行 ID 和字面量分组。JSONL root、本地附件 dshHome、JSON Storage root 分别指向真实组件候选。覆盖整行 config，保留其余字段；会话物理压缩参数取实际恢复写入所用的 SDK 默认值。来源禁用状态保留并提示。
- 未选择会话或工作区时使用新 home 内的空目录，明确记录缺失范围；不猜原目录。新工作目录为空，原会话和工作区的历史目录引用保持，项目文件尚未恢复。
- 通过 Node SQLite backup 克隆已验证的自有 checks/tasks/media 数据库到新应用 home，保留记录、编号、顺序及作品引用。新副本暂停 tasks 的 tracking/querying，原组件候选与来源保留原值。这里只装配已覆盖的三类记录，不包含其余 MCP、画布或更新状态。
- 在最终覆盖层暂停 SDK 定时任务、工作区注册器及上报模块，保留未完成工作区变更而不执行；禁用官方美术模块。权限和程序仍须审阅。配方记录具体参数、目录、待办事项，不提供自动启动或激活。
- 实际 Host 从可信公开 profileContext 提供 SDK 安装锚点；浏览器不能传入它。底层组合库未显式启用装配时保持原行为。新配方和覆盖层一同进入原候选文件基线，不改变索引格式。
