# 0102 · 将知识库装配到恢复应用

应用配置已经能读回会话与工作区，但本地知识库仍留在独立组件目录，恢复后的应用无法直接使用。本次将已验证的知识逻辑数据装配到新应用 home，关联恢复资料原件，保留原项目和历史授权记录，暂停模型访问与检索后端以待审阅。

## 实现

- 真实知识恢复模块直接提供类型化候选结果给组合装配器。使用实际 collection 映射，不猜路径、不遍历任意 JSON 字符串；不改变已有布局或候选索引格式。旧适配器没有提供映射时仍提示待关联。
- 只读取新组合候选内的原知识组件。经既有只读快照、严格 schema 和逻辑行导入重建应用目录中的知识库及 FTS；原库、组件库、文档/片段编号、绑定序列与历史授权均保留。所有映射完整匹配后才创建目标，拒绝越界、链接、重复、缺失或错误的 collection 映射。
- 仅在新副本更新资料根目录、增加 collection epoch、关闭 agent_enabled。原项目目录绑定和历史 grants 原样保留，旧会话下次检索会被拒绝；不删除历史来规避授权检查，也不自动把不同项目合并到一个目录。
- 原检索后端记录逐字保留供审阅，运行设置保留原选择但默认暂停。整个 config 表达式或程序不会为此执行；不创建提供者或发起云端请求。
- 支持只恢复配置与知识库，无需同时恢复生成记录。真正没有知识数据库的来源保持缺省，不把它初始化成已恢复的空库。目标文件独占创建，取消或失败只清理本次新建文件，已有数据库或设置不覆盖。
- 配方记录实际应用数据库、资料映射、新旧 epoch、历史授权数量及后端审阅位置。项目目录、模型授权、技能及其余状态仍须继续处理；没有激活按钮或自动切换运行应用。
