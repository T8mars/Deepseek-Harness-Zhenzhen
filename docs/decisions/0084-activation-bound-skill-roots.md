# 0084 · 将技能备份目录绑定到实际激活

2026-10-22。0083后的隔离探针复现了一个来源一致性问题：filesystem provider
在构造时解析默认目录。若插件后来改变进程环境，`Entry.fiber.config` 中未填写
的字段仍是缺省值，备份再次解析时可能选中另一目录。已验证配置不等于保存了
所有构造时解析的默认值；之前的合同没有覆盖这一区别。

新增自有 `SkillSourceTracker`，通过已发布 Cordis 的公开 `internal/config`
waterfall，在 Loader 插值后观察根配置，原样返回配置；只在该 Fiber 进入
ACTIVE 时提交快照。配置预校验不能替换正在运行的来源，卸载时快照失效。
只保存路径默认值及当时 cwd，不复制环境、配置树或凭据，也不读取 provider
私有字段。不完整的观察不会改变应用启动行为，备份会明确拒绝。

自有 bundle 给根 `skill-filesystem` 补充 `zhenSkillBackupSources` 服务依赖。
观察器先安装，再提供此服务，provider才继续启动。后续 preset/provider 的
激活由同一公开事件观察。没有改上游文件、启动内核、原 provider 配置或
技能优先级；原静态依赖 `skills` 仍保留。

备份采集使用已经解析的目录，新增 `host-local-resolved` 来源模式，避免归档
组合时再次回退到当前环境。启动时没有 bundled 根，之后出现的环境目录也不
会被加入。没有观察到的旧活动来源，只有自包含的绝对路径配置可直接使用；
仍需默认值的来源拒绝备份，不主动重启或重写该来源。
