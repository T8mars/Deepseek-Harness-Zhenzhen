# 0110 · 启动只使用已安装扩展的补丁

开发项目把自身扩展注册为 npm workspace，安装 CLI 的模块锚点因而能先找到源码包。真实 CLI 即使已经把另一份扩展安装到临时配置，组合配置仍取自工作区；改变当前目录不能解决。这会使“已安装版本”和实际配置不一致，也让开发改动提前进入运行配置。

本次移除根项目对自身 bundle 的 workspace 注册，将四项已有固定运行依赖明确列为根开发依赖，供构建与测试使用。扩展自身的依赖、peerDependencies、名称和发布结构不变。锁文件仅移除自身链接及已标记 extraneous 的来源记录；经 npm 再校验，所有其余版本、来源与完整性摘要保持。

启动入口增加来源检查：旧链接残留时，即使准备摘要未变，也在持有原有运行租约后执行无生命周期脚本的依赖准备。核对成功才保存准备记录、构建和启动。直接调用已准备入口时，也在创建租约或访问配置前拒绝冲突，并提示可直接使用的启动和修复文件名。
