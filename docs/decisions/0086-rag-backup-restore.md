# 0086 · RAG 数据与原件的独立恢复候选

2026-10-22。`dsh-zhen/backup` 新增 `prepareRagBackup`、
`writeRagBackup` 和 `restoreRagBackup`。只用 DSH 自有服务和公开 Node SQLite
接口，不改上游或画布。Host-only 入口使用现有知识库；尚未打开的自有 schema3
文件用只读连接捕获，不触发建库或迁移。不存在的库仍记录不存在，旧 schema
明确拒绝，需要先通过正常知识库升级流程处理。

六个逻辑表按有界 NDJSON 导出，恢复时建立已知 schema 并重建词法 FTS。
归档不能携带可执行 SQL、触发器或后端函数。固定引用 ID、PDF 页码、DOCX
正文行号、权限 epoch、工作区绑定与计数器高水位保持；历史失效和孤立会话
grant 仍保留为拒绝依据，不通过删旧记录使原权限重新有效。

每份已索引原件单独保留当前完整字节，标明与上次索引一致、已变化或缺失。
索引缓存仍保留原文本。运行后端与磁盘设置分别记录，包括无效或已卸载后端的
设置；候选只存数据，不注册后端、不重绑路径、不恢复外发授权。

最终归档沿用 AES-256-GCM/scrypt。捕获期间的 SQLite 副本位于新建私有临时
目录，结束即清理；512 MiB 快照、32 MiB 清单、4 万份原件、每表 500 万行
和每行 1 MiB 上限均拒绝超量，不截断数据。临时导入诊断不属于持久状态，
清单明确不包含；未索引文件也不冒充完整资料目录备份。

保留的 lease 同时检查本连接 `total_changes()`、其他连接 `data_version`、
后端/来源对象/策略和原件变化，供未来总归档结束时再次核对。独立流结束的
检查不能代替所有组件共同的最终屏障。完整认证先于候选目录创建；后续
严格校验记录、行、关联、高水位、路径和摘要，失败或取消只清本次候选。

专项发现并修复调用方原地替换对象逃过来源检查的问题；不同公开入口独立
打包造成的 Error 类身份差异改为仅映射固定自有错误代码。初轮失败日志保留。
DOCX 后续一次失败来自夹具省略必填 provider，补全调用，生产授权条件不变。
