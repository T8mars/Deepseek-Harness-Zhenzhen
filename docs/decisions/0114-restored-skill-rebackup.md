# 0114 · 恢复技能再次备份与连续恢复

恢复应用的技能使用独立资源和项目入口，普通文件系统库存会漏掉对应项目，并把系统为审阅设置的暂停误当成用户禁用。本次新增恢复来源适配，接回原有备份任务；完整 Host 使用同一个入口备份技能和应用配置。

新来源读取本应用生成的配方、项目清单和每个配置档的完整应用覆盖设置，核对实际发布的 Loader、文件系统服务及完整配置。每个配置档与入口获得独立库存标识，保留原用户启用偏好；未关联项目的资源也保留。库存 v3 分别记录逻辑项目范围和普通物理资源路径，旧 v1/v2 继续严格读取。普通来源仍写 v2，不放宽归档链接规则。单份 v3 最多2048个提供者、128个项目，技能资源总范围仍最多1024；超限明确拒绝，不截断后宣称完整。

原始清单修订、配方、覆盖设置和入口身份的检查保留至整份组合归档结束；不能用后来新解析的来源续掉最初检查。配置快照将各配置档的自有应用覆盖设置追加到逻辑快照，原 SDK 配置文件不写入。仅备份配置时不读取技能正文或要求技能资源继续存在。

连续恢复还复现了目录关联问题：会话头保留原始项目，当前目录已经通过历史事件改变。应用回执现在另记由公开 SDK 冷投影按页计算的恢复前有效目录，知识库与技能按这项当前关联迁移。原会话头、历史、分支切分和目录事件保持，不以直接改写持久化格式解决问题。

实际 Owner 完整任务暴露了 Windows 临时 SQLite 名称问题：临时文件路径252字符时可打开，但日志文件导致建表失败。候选索引改用同目录更短的独占随机临时名，保持原子创建、身份检查和数据库格式。
