# 0098 · 恢复候选的实际摘要与文件复核

0097 生成了独立候选，但只显示目录和任务完成状态。本次补充实际恢复数量、待处理问题和候选文件复核，供后续统一装配与激活使用；完整应用恢复仍未完成。

## 实现

- 六个摘要直接取自已有恢复模块的返回值，包含配置/依赖、会话附件、全部技能来源及保留版本、知识原件状态、自有生成记录/作品索引、工作区与待处理引用。没有详细结果的第三方组件明确标记明细不可用，不用零冒充未知。
- 所有组件恢复后，在整个新候选目录建立创建时基线，内容通过流式 SHA-256 读取；再检查一次完整元数据库存以拒绝扫描期间变化。只读普通文件，不遍历链接目标；目录/文件链接仅记录自身指向。特殊文件、根链接、目录逃逸、超限或取消不建立有效基线。失败仍清理整个新候选。
- 基线保留在原 Host 任务中，Owner 只能按该任务 ID 查询或复核，不能提交任意文件路径，也不信任候选里可编辑的回执作为基线。复核显示「创建时记录 / 当前一致 / 已变化 / 不可读」；完整读取未完成时不会报告一致。
- 一个 Host 同时只进行一项备份、恢复或候选扫描。同一候选并发复核复用一次读取；取消复核不撤销已成功的恢复，之后可再次检查。Host 卸载会取消并等待读取结束。
- 新增两个 Owner Remote，不增加 Agent 工具或执行入口。创建时摘要自动读取，当前字节复核由用户点击发起；密码不参与复核。前端区分创建时间与当前检查时间，显示数量和目录/权限待处理项，处理旧 API、迟到创建摘要、重复点击、取消和卸载，并在校验期间禁用父页面的新任务。
