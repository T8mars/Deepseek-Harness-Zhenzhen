# 0100 · 恢复目录清单与准备情况检查

各组件已经生成独立候选，但总候选没有保存配置、会话、知识库与其他目录的类型化对应关系，后续统一回绑只能猜路径。本次从实际恢复模块返回值生成布局清单，并在「恢复候选预览」增加「检查恢复准备情况」。本次不执行目录回绑、程序启动或应用激活，完整恢复继续开发。

## 实现

- 六类恢复包装器记录实际返回的路径、配置档、缺失依赖与当前安装引用。会话目录来自已有JSONL写入参数，附件记录的是公开服务的dshHome；知识、技能、生成记录及工作区均读取各自真实候选结果。没有复制原始配置、表达式、程序参数、权限或凭据。
- 组合恢复在最终基线建立前写入独立的布局清单。严格schema约束已知角色、文件类型、唯一角色/配置名、六类范围和全部最多128项配置；记录路径须在该组件和总候选内部，逐层拒绝链接或目录逃逸。未知适配器未提供布局时明确记录明细不可用。
- 原候选基线与SQLite索引格式保持不变。读取布局前后固定文件身份和字节摘要，中间复核完整原候选基线；布局单独可编辑的回执不能替代原基线。没有布局的旧候选仍可校验，并明确提示旧记录不能提供准备明细。
- 新增一个严格Owner Remote，共十二项备份接口拒绝匿名；没有新增Agent工具或任意路径入口。与备份、恢复、文件复核、移除及注册保持单项互斥，同候选并发准备检查复用一次读取，取消和卸载会中止并等待读取结束。
- 页面手动发起检查，显示实际目录、全部配置档和依赖/权限/目录/未覆盖范围事项。返回同一次完整复核的数量快照，迟到的初始摘要不会覆盖它；旧API、切换候选、双击、错误根和取消均受保护。此处没有启动或激活按钮。
