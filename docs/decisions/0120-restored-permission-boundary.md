# 0120 · 恢复会话不沿用历史写入权限

恢复副本此前只标记“权限需要重新审阅”，实际 SDK 仍会重放会话中的旧 `sandbox/mode` 和 `approval/policy`。最小实证中，副本回执声称没有恢复权限，实际策略却是 `danger-full-access` 和 `never`。该状态不能作为安全的恢复起点。

现在只在新应用副本中追加已发布 SDK 的三个普通权限事件，将已存在的历史权限覆盖为只读、逐次询问。原组件、原会话头、历史事件前缀及子 Agent 的继承边界保持。没有目录映射的会话同样处理；已具有完整只读/询问状态的历史不重复追加。所选目录变更仍放在最后，目录顺序保持原调用顺序，其余会话随后处理；遍历按线性时间去重。

恢复应用的整行覆盖还按模块身份处理权限预设、沙箱策略和审批策略。默认变为只读/询问；不把名为 `read-only` 的自定义预设当作安全证明，原有其他预设和配置字段仍保留供当前用户重新选择。无法检查的整块表达式不产生可执行启动配方。源配置、源备份和上游代码不改，凭据不进入恢复。

三个 SDK 类型依赖与 peer 均钉在已发布的 `0.2.1-rc.2`。SDK 默认预设表由契约核对；没有改会话存储格式、上游事件定义、Desktop IPC 或原生画布。
