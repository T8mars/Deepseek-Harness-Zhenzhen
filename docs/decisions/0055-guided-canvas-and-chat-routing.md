# 0055 · 画布连接向导与会话入口统一

2026-10-21。用户现场先因旧工具/源码工具与桌面不配套而反复失败，配对后又出现
会话加载全局画布技能、绕回另一份 CLI 的排查循环。用户要求普通用户无需找目录、
填写实例 ID 或理解协议，并授权必要的真实 API 测试。本轮只修改 DSH 扩展。

连接页默认给出三步向导。Windows 通过固定、有时限和输出上限的系统只读查询，
读取正在运行画布的可执行文件路径，优先展示该安装随附的工具；受管导出为备用。
检测只读元数据和计算摘要，不执行候选或自动信任。用户点击连接后仍绑定所展示
的完整摘要；目录、实例 ID 和原样兼容报告收进高级/诊断区域。

新增 Owner RPC 单独执行原生精确握手，区分未启动、多实例、原选择已失效、工具
变化、版本不匹配及可配对。多实例点选，不要求手填 ID。只有握手通过才能配对，
只有原生会话检查已配对才显示工作流/生成面板。额外权限仍显式选择，画布窗口
仍是审批权威。公开 `canvas_status` 及 compat 原样保留，不用状态 HTTP200替代握手。
诊断携带所检查的配置绑定；其他窗口在检查期间改连接时，服务端及界面均拒绝把
旧结果显示为可配对，并提示重新检测。C55覆盖此真实异步交错。

通过已发布 `systemPrompt.section` 扩展和内置技能 1.0.2，引导会话使用当前 DSH
画布 MCP，说明 `pairingRequired:true` 是认证策略，失败时停止并进入连接向导，
不转向全局 CLI 反复排查。保留用户其他技能。创作空间增加常驻“画布连接”等导航，
明确区分方案、工作流应用和作品生成。这里是模型指引，不宣称它是 shell 安全沙箱。
