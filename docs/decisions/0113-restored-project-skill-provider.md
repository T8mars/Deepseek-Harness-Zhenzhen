# 0113 · 恢复项目技能的公开 SDK 提供者

恢复项目目录后，技能文件仍位于独立候选。将这些目录加入全局技能来源会让其他项目读到同名技能；直接写入用户选择的项目目录也不符合恢复边界。本次新增服务端薄适配层，用经过验证的会话原目录与新目录关联，在对应项目中委托已发布的文件系统技能提供者读取候选资源。

每个配置档保留原提供者名称、完整配置、优先级、相对资源入口和原有停用状态。未知项目只保留原全局来源，不获得其他项目技能。候选中的项目技能清单默认待审阅；原 SDK 行继续暂停，生产审阅放行与应用激活尚未实现。测试中的显式放行只用于独立 TEMP 验证，不代表已有生产批准流程。

固定 SDK 会向父目录寻找 `.git`，候选位于另一个 Git 项目内部时可能错误读取父项目技能。契约先复现这一问题，再在本次新建的候选技能入口内创建查找边界文件；不会在用户所选目录、原项目或画布目录写文件。文件和入口目录身份均在读取前后核对。SDK 的空 bundledSkillDir 会指向进程目录，因此适配层使用明确的、被记录为不存在的候选内路径，防止环境变量或当前目录成为额外来源。

清单修订、项目目录身份、入口及已知链接目标变化会使缓存失效；取正文时再次核对，拒绝跨项目候选、撤权期间的读取和来源替换。清单观察器共享，项目目录观察器有界；原 SDK 文件观察和取消机制保留。
