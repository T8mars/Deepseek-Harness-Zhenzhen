# 0103 · 恢复应用中的技能来源与版本

恢复的技能原先留在独立组件目录，新应用仍会寻找旧目录；正常构造技能服务又会应用原来的待更新版本。本次将真实技能状态装配到新应用的数据目录，保留全部版本、来源和用户选择，另行暂停调用与自动下载，等待恢复审阅。

## 实现

- 从实际技能恢复结果传递类型化映射；只读已经恢复的组件，不读取原目录，不执行归档代码，不改变布局或候选索引格式。
- 在新应用目录实际写入市场数据库、本地来源、完整 GitHub 保留版本及原有目录缓存。个人副本、active/pending/latest、禁用项、自动更新偏好与持久缓存是否原本存在均保留。本地来源的目录身份对应实际恢复资源。
- 新增本项目自己的审阅记录。实际服务通过明确的审阅模式读回原状态；市场以只读数据库打开，启动不提升 pending，不挂载模型技能、不自动检查或下载。Owner 仍可查看原有选择。缺失审阅记录是普通启动，损坏记录明确拒绝，不能退回普通启动应用待更新版本。
- 固定已发布文件系统提供者要求用户技能位于 home/skills，项目技能位于项目的 .dsh/skills 与 .agents/skills。恢复资源本身不具有此层级，因此在候选内建立目录入口，分别指向已验证的恢复资源；不猜其父目录、不把项目技能提升成全局技能。共享项目和多个提供者复用相同项目范围。
- 应用覆盖按模块名称或实际捕获的文件系统条目 ID 匹配；整行配置保留其他字段，更新已知目录并暂停提供者。未选择技能时配置为空的新目录，避免回读原有技能。未知映射保持待处理。
- 目标独占创建，取消或失败只清理本次新建内容。原组件、原服务和先前候选不覆盖；没有激活入口或自动切换运行应用。
