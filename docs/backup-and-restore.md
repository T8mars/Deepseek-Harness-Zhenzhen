# 加密备份与还原

当前提供 Host 库入口 `dsh-zhen/backup`，已有会话/附件、公开配置、软件包、完整技能库存、RAG、部分自有记录和已打开工作区域的备份与独立恢复候选。创作空间的「备份恢复」页面现可选择六类范围、创建一份加密总归档、查看进度和文件，并将所选文件恢复为独立候选。统一路径/身份回绑与候选激活仍未完成，**不能作为完整 M2/L2 还原验收**。

新生成的组合候选现可装配会话、附件、工作区库存和三类自有记录的应用路径，保存 `dsh-zhen-application-restore.json` 与每份配置的独立覆盖层。实际 Host 使用当前可信 SDK 锚点生成；底层库需显式提供 `application.installAnchor`。受控官方 CLI 已在示例原目录离线后读回数据，尚未提供候选启动/激活按钮。知识库、技能、权限和项目文件等仍须继续装配和审阅。详情见 [0101](decisions/0101-restored-application-bindings.md)。

应用副本会暂停旧任务追踪、定时任务和工作区待变更执行；原组件候选保留全部历史状态。记录装配不恢复凭据或旧执行权限。不要手动运行配方来替代尚未完成的激活流程。

知识库现在也会通过既有逻辑导入装配到新应用目录，资料根指向实际恢复原件。原项目绑定、文档和片段编号、全部历史授权保留；新副本的集合 epoch 增加，模型访问关闭，检索后端保留选择但暂停。只恢复“配置＋知识库”也可装配；原本没有数据库时保持缺省。项目目录和权限仍需审阅，不能据此直接切换应用。见 [0102](decisions/0102-restored-knowledge-home.md)。

| 已有 Host 入口 | 范围 | 当前限制 |
| --- | --- | --- |
| writeSessionBackup / restoreSessionBackup | 全部公开存储会话、分叉和引用附件 | 不恢复 Agent 执行；候选未激活 |
| writeProfileBackup / restoreProfileBackup | 公开 profile 清单、机器 patch、配置覆盖及兼容记录 | 原凭据不含；Desktop 仍需专用入口；不启用候选 |
| writeProfilePackageBackup / restoreProfilePackageBackup | 配置与完整已选软件包资源、公开依赖路由及离线装配 | 不运行包管理器、脚本或旧 SDK；原工具专有 PM 文件未捕获 |
| writeSkillInventoryBackup / restoreSkillInventoryBackup | 全部声明根、被遮盖/禁用定义、保留版本、个人副本和管理状态 | 本地/GitHub/feed 候选保留；不自动启用或下载 |
| writeRagBackup / restoreRagBackup | 自有逻辑表、FTS 重建、引用身份与已选来源资源 | 路径与授权仍需整体回绑、审阅 |
| writeOwnedStateBackup / restoreOwnedStateBackup | 自有 checks/tasks/media 和已选导出文件 | 不包含其余 MCP/画布/更新等自有状态；旧记录不授权执行 |
| writeWorkspaceBackup / restoreWorkspaceBackup | 已打开公开域的全部记录、顺序、归档、置顶及待变更 | 冷域明确不可用；只含目录引用，不含这些目录的项目文件 |

这些是组合备份的组件，不是同一份完整应用归档。恢复均生成独立、未启用的候选；组件成功不能证明全应用已经恢复或当前用户资料已经通过灾难恢复验收。

## 已实现的会话范围

- 通过 `SessionStore.flush` 和 `SessionPersistence.flush/list/open/read/stat` 读取逻辑数据，不复制会话的私有存储文件，不修改格式。
- 保留公开 header、完整事件、原始会话 ID、父子关系和精确 `inheritedEventCount`；已支持的未知可忽略事件原样保存。未知必需事件和需要迁移的会话拒绝备份或还原。
- 使用已发布 `sessionLogZipEntries` 收集规范事件中的附件，引用仍由原 SDK 判定。任意插件数据里的同名字段不被猜成附件或文件路径。
- 通过本地附件服务读写文件；规范化图片使用公开 `commitPreparedImageFile` 和读取验证保留原始身份，不重新压缩、不改写事件中的引用。当前明确支持已发布本地后端的 `sha256:` 身份。
- 备份前后执行持久化屏障，比较同一实例的全部会话集合、不透明 revision 和活动会话的公开事件序号；事件仍在缓冲区也会拒绝。源内容变化、服务被替换或活动会话尚无持久化所有者时拒绝发布，不静默遗漏。
- 附件按引用 SHA-256 核对实际图像和文件流字节；读取失败不把内部路径或底层异常消息作为可展示错误。

## 组合末尾的来源检查

prepareSessionBackup、prepareSkillInventoryBackup 和 prepareWorkspaceBackup 返回 Host-only 的 records()、assertCurrent()、close()。流只能消费一次，关闭可重复调用；关闭不改变原数据，也不关闭原工作区域。

组合方需要保留所有来源，在最后一个组件写完后再次执行全部 assertCurrent()，再发布总归档，最后统一关闭。仅消费完某一组件的流并不能代表之后的数据仍未变化。配置、包、RAG 和自有记录已有对应保留检查入口；统一装配仍在开发。

实际 ZhenService 提供 sessionBackupLease、skillBackupLease、workspaceBackupLease 等 Host 方法，未暴露成模型工具或原始浏览器 Remote。缺少服务时拒绝，不为备份初始化管理器。工作区域通过公开 domain/changed 和身份检查识别写后恢复、提供者替换及 Host 卸载；找不到已开域时不能将其视为空数据。

工作区候选保留创建/删除中的待变更，且不启动 WorkspaceRegistry 完成它。未排序记录、缺失记录和 pin/archive 冲突保留并标记需要审阅，不默默修复。

## 加密与文件行为

文件格式为 `DSHZBKP1`：随机盐、固定 scrypt 参数和随机 nonce，AES-256-GCM 保护记录及其元数据。密码至少 12 个字符、UTF-8 编码最多 1024 字节，不写入凭据、环境变量或日志。密码无法从归档恢复。

写入只生成加密的独占临时文件；同步完成后以不覆盖已有文件的方式发布。正常文件系统优先使用硬链接；不支持时使用独占复制。独占复制的中断可能留下不完整加密文件，读取端会拒绝它。归档没有压缩层。

读取先在系统 TEMP 创建有界的独占加密快照，完整验证认证标签；密码错误或内容被改动时，不创建还原目录。随后流式解析，所有还原工作只在新建候选目录中进行，全部通过才返回候选路径。失败时只清理本次拥有的目录，不接触已有用户目录。

默认预算：加密归档 4 GiB、单记录 1 GiB、元数据 64 KiB、10 万条记录；会话逻辑内容 32 MiB、1 万个会话、本地图片 20 MiB。超限明确拒绝，后续界面需要展示原因与可选范围，不截断内容冒充完整备份。

凭据服务完全不参与，manifest 标记的是 `credentialStoresIncluded:false`。用户自己写进会话或附件的敏感文字仍属于其原始内容，因此归档始终加密；不能声称自动识别、删除所有敏感字符串。

## Host 调用

```ts
import {writeSessionBackup,restoreSessionBackup} from 'dsh-zhen/backup';

// resolve 在每次核对时重新取当前公开服务，便于识别服务替换。
const resolve=()=>({
  sessions:ctx.sessions,
  sessionPersistence:ctx.sessionPersistence,
  sessionQuery:ctx.sessionQuery,
  attachments:ctx.attachments,
});
await writeSessionBackup(absoluteBackupFile,password,resolve,{signal});
const candidate=await restoreSessionBackup(
  absoluteBackupFile,password,existingCandidateParent,{signal},
);
// candidate.activated === false；此处没有恢复 Agent 执行、替换 profile 或切换应用。
```

还原用全新公开 Cordis/Session/JSONL/本地附件服务；查询服务 `openAt:'never'`，不打开查询数据库。已有应用的会话、配置、凭据和任何画布数据不参与。候选目录不具备完整应用配置，不应直接当作运行环境切换。

## 验证与剩余工作

C88 验证流式加密、随机性、错误密码、损坏、预算、不覆盖、取消、元数据约束及临时快照生命周期。C89 使用固定已发布 SDK 和全新系统 TEMP，验证分支继承、257 个事件分页、活动持久化屏障、未知可忽略事件、图片与文件身份、缩放前尺寸、源变化拒绝，以及缺失附件/重复 ID/未知必需事件后的清理。

配置/软件包、技能、RAG 和部分自有状态的独立候选已实现，各自证据见对应决策；C110/C111 增加保留到组合末尾的来源检查及公开工作区域候选。所有这些测试都只使用 EXAMPLE TEMP 资料。

冷工作区域、其余 MCP 程序/数据/维护档案与授权、DSH 自有画布计划/提交/回执和更新/美术引用等状态、跨组件路径及身份回绑、候选激活界面和完整 L2 验收继续开发。画布原生仓库、安装、配置或运行目录不由本 Agent 修改；所需原生变更仅通过交接文档处理。普通升级不应拿候选替换正在运行的用户服务。

## 在创作空间使用

进入「创作空间 → 备份恢复」，选择文件夹与范围，输入至少 12 字符的密码并再次确认，点击「创建加密备份」。默认文件夹在首次创建时生成，也可用现有目录选择器选择其他位置。服务未就绪的范围不会默认备份；页面明确显示未覆盖内容。

恢复时点击「查看备份文件」，选中一份文件，填写原密码和候选存放文件夹，再点击「校验并生成恢复候选」。整份文件和各内层加密组件先通过校验，才写入新的候选目录；不会切换当前应用或执行旧任务。本入口生成记录仅备份作品索引，不复制原件。

可离开页面后返回查看原任务。运行进度仅保留在当前 Host 内存中；已生成的恢复候选另有持久记录，应用重启后可在下方列表继续查看和复核，不会自动重做。回执丢失时按原请求编号查询，暂时无法确认时可重新检测，避免自动重复创建。密码不保存，也无法找回。

## 查看恢复候选

任务成功后，「恢复候选预览」显示创建时的实际数量、缺失/变化原件、未复制作品以及目录、权限等待处理事项。点击「校验当前候选」会把候选目录内普通文件及链接自身的指向与创建时基线比较；不会读取链接目标或激活候选。应用环境、原目录关联和权限仍须统一核对，字节一致不是完整恢复成功的证明。

复核可取消，并可稍后重试；已成功的恢复保持不变。页面区分创建时记录、当前一致、内容变化和不可读。基线由自有SQLite记录保存，重启或内存任务淘汰后仍可从「恢复候选记录」选择原候选。列表每页20项，可刷新与翻页；复核不需要再次输入密码。

「移除此记录」只移除索引，不删除候选目录和原备份。若候选已生成但记录保存失败，先保留显示的路径，点击「重试保存记录」即可复核并保存同一候选，不会重复解密恢复。索引不可用时页面明确提示；旧Host仅支持内存时也会说明重启限制。这个索引本身尚未加入六范围归档。


## 检查恢复准备情况

在恢复候选预览中点击「检查恢复准备情况」，服务会复核整份原候选，再检查保存的恢复目录、应用配置及依赖事项。页面显示各范围的实际位置、全部最多128个配置档，以及目录关联、权限审阅和未覆盖数据等事项；不会执行程序或切换应用。此检查可能需要完整读取候选，可用原编号取消。

旧候选没有目录清单时会明确提示；它的文件复核仍然可用。从原备份重新生成可补齐新清单，无需手工猜目录。新清单也由原文件基线保护，不能仅编辑回执来跳过校验。当前检查不是完整可启动环境的证明，统一回绑和激活仍在开发。


## 恢复应用中的技能

同时选择应用环境与技能时，新候选会装配完整市场版本、本地来源、GitHub保留版本与原有缓存，保留个人副本、禁用项、待更新版本和自动更新偏好。审阅期间暂停调用和下载，重启不应用 pending；不把项目技能提升成全局技能。原应用、原资料与原组件不变。

只恢复应用环境而不选择技能时，候选文件系统技能提供者使用新的空目录并暂停，不回读旧路径。旧候选配方没有 skills 字段时仍属于待装配。目录入口依赖本机文件系统能力；项目工作目录关联已接入待审阅提供者，审阅放行与激活仍未完成，不能视为整个应用已经恢复可用。

同时恢复应用环境、会话和技能并采用项目目录时，候选会保留每个项目自己的技能范围、同名优先级和相对资源。不会向所选文件夹写入技能，也不会将项目技能变成全局技能。原停用来源保持停用，清单默认待审。

在恢复应用正常打开后，进入「技能市场」或「备份恢复」可查看「恢复技能审阅」。核对当前配置的来源、原启用项和全部关联项目；每页20项，可翻页。勾选确认后点击「允许这些恢复技能」，只放行当前配置原来已启用的文件夹技能；原全局作用范围和项目隔离保持，其他配置分别审阅。点击「暂停这些恢复技能」可撤销，已有缓存和读取中的正文也会重新检查。

这项决定独立保存，绑定原来源清单的摘要；来源或目录身份变化时不能继承。读不到回执时点击「检查恢复技能」读取实际结果，不自动重复提交。再次恢复得到的新 home 仍待审；旧权限不随备份转移。市场、本地导入和 GitHub 管理来源的放行、统一权限以及整个应用的启动/激活仍需继续。

完整应用中的恢复技能可通过原备份入口再次备份。系统保留各配置档的原启用偏好、完整覆盖设置和已关联/未关联项目资源；不会将待审阅造成的暂停当成用户禁用。继续使用原来的备份密码流程，所选项目文件夹不写入文件。

缺少配置入口或项目来源清单的旧恢复 home 会明确拒绝不完整的技能库存。请保留已有数据和原始备份，并用原始备份重新生成新候选；旧 home 的自动迁移尚未实现。配置或来源在备份期间改变时，本次任务失败，不自动重试或生成遗漏项的完整性声明。

连续恢复时，技能与知识库按会话恢复前的有效目录关联到新目标；会话头保留原始项目标识，历史不改写。第二次恢复也会保留未运行配置档的应用覆盖设置。整个候选依然需要审阅，不恢复旧授权或自动激活。

## 会话副本与项目目录

同时选择应用环境与会话时，恢复应用使用独立的会话和附件副本，原恢复组件保留。Host 组合接口可传入 `application.sessionDirectories`，每项包含 `sessionId` 和已存在的绝对 `directory`。系统核对目录身份，只向新副本追加公开目录变更事件；不可变会话头、原历史及分支继承不改，也不复制或改写所选项目文件。页面现在按项目解析这些关联；只有明确采用的选择才进入新的恢复请求，权限仍需另行审阅。

未选择的会话保留原目录并提示待关联；目录缺失或中途被替换时拒绝。没有恢复权限、激活应用或继续旧任务。受控 CLI 启动可改变新配置档，使用过的候选会被原基线标为变化，不能沿用“原样未变”的验收结果。

在同时包含应用配置和会话的候选中，可点击「读取项目列表」，按原始项目目录分组选择现有文件夹，再点击「采用这些目录」。选择可跨页保留；通过提示中的链接返回恢复表单，核对原备份，并在「恢复密码」中输入这份备份的原密码。再次生成的是独立新候选，原候选保留。

浏览器不需要输入会话编号；Host 从原候选解析所选项目，并在新解密数据中核对原目录。更换备份、存放位置、候选或连接会清除旧选择。来源记录不可用时明确提示重新生成，不当作请求回执丢失。新建备份密码与恢复密码各自填写，均不保存。


## 工作区应用副本

同时恢复应用环境和工作区时，应用使用独立工作区副本，保留组件继续保持原样。工作区名称、编号、目录、会话顺序、置顶、归档和待处理历史都会保留；恢复期间不继续待处理操作。

会话的当前工作目录与工作区分组不是同一项设置。发布 SDK 仍按原会话头核对分组，因此选择新的会话目录不会直接改写工作区路径。统一项目关联和权限审阅尚未完成，注册器保持暂停，恢复应用不会自动激活。

如果候选同时包含应用环境、会话和工作区，选好项目目录后还可勾选「为新目录建立继续会话入口」。采用目录，再输入原备份密码，系统会在新的独立候选中创建继承原历史的继续会话，并将工作区副本关联到新目录。原会话、历史和原工作区副本全部保留；子 Agent 保持原身份。

这个选项默认关闭。所选目录冲突、工作区只选择部分会话或目录发生变化时，恢复会给出提示，不合并项目或丢弃会话。目录选择仍不授予文件访问权限；工作区注册器、旧任务及模型调用保持暂停。RAG、技能范围和权限的统一审阅及应用激活仍在开发中。


## 项目目录与知识库

候选同时含应用环境、会话和知识库时，采用新的项目目录会同步更新与原目录完全一致的知识库绑定。资料空间名称、集合与检索引用保持；未选空间保留原目录。继续会话入口的勾选不影响这项关联。两套空间可一并互换目录；目标已被未选空间占用时会提示冲突，不自动合并。

这只准备新候选的关联，不恢复模型访问或旧会话授权。打开、启动或修改候选后，其文件基线可能发生变化；需要重新核对，不能继续沿用使用前的完整性结果。
