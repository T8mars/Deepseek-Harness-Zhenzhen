# 连接本机创作技能

技能市场中的“连接你自己的技能”支持现有的本机 SKILL.md。它保留原始
目录，引用文档、脚本、模板和图片仍位于原来的相对位置；不会把整套技能
压缩成只有一段提示词，也不会复制内容到公开发布包或改写原许可。

选择“单个技能”，填写直接含有 SKILL.md 的绝对目录。例如：

```text
example-creative/
  SKILL.md
  references/guide.md
  scripts/example.py
  assets/example.png
```

选择“整个技能库”，填写包含各个技能子目录的绝对目录。扫描只看一层
子目录中的 SKILL.md，不把根目录 README 或更深层的文档当作技能。隐藏
条目、链接入口被跳过，缺失或格式错误的技能会计入无法识别数量。界面
展示有效清单，并可逐项查看正文。确认清单后勾选信任目录及后续修改，
再连接；扫描期间发生变化的正文需要重新预览。

SKILL.md 使用 UTF-8 和 YAML frontmatter，包含 kebab-case `name` 与
`description`，正文不为空。支持 CRLF、普通 YAML 别名，以及上游标准的
`disable-model-invocation` / `user-invocable` 字段。前者关闭模型自动加载，
后者控制是否出现在手动调用入口；旧的 camelCase 字段需要改成标准字段。

连接后新建会话或刷新页面，在 `/` 中调用。模型加载使用 DSH 原生 `skill`
工具，原资源目录通过公开的 resourceBase 传递。技能指令对特定软件、
模型、绝对路径和外部工具的依赖仍需配置；连接本机目录不会自动安装依赖、
运行脚本、批准工具调用或付费生成。访问和执行资源继续使用应用的工具
权限；资源目录本身不是文件系统沙箱。

这里信任的是可变的本机来源。目录中的正文修改及技能库新增项会用于后续
加载，约一秒的文件状态轮询会使技能目录缓存失效。已经进入会话的旧指令
无法收回，因此改动或停用后应新建会话。单个库中的同名项按子目录排序
选择首项；多个本机来源之间保留较早连接的来源，其余标为“同名项未选中”。
与项目或其他提供方冲突时仍遵守 DSH 的技能优先级。

停用阻止此连接的后续发现与加载；其他提供方的同名技能仍可能存在。断开连接只移除连接记录，原目录保留。重新启用
需要再次扫描和确认。目录被替换后，原目录身份校验不通过，需要重新确认。
本功能没有创建版本快照，原文件回退由用户或其 Git 工作副本管理。

Git 工作副本更新已有文件后，会按同样方式被重新发现。第三方公开 GitHub
下载由[独立的快照提供方](github-skills.md)处理；发布源的纯文字候选与自动更新仍由原来的
独立策略管理，不能将本机目录信任当作远端可执行包的自动更新授权。

每次扫描最多 512 个顶层条目、128 个技能目录和 8 MiB 指令文本，单份
SKILL.md 最多 128 KiB。最多连接 16 个来源。参考资源不在扫描阶段递归读取。
连接记录保存在自有 schema-1 `local-skills.json`，仅记录路径、目录身份、
模式、信任时间和开关；不保存正文、许可副本、凭据或资源内容。旧的技能
市场 SQLite schema 3、发布源策略和个人副本保持独立。
